# ТЗ для Claude Code — Octane Podcast (автономный тестовый вариант)

> Это задание для агента (Claude Code). Прочитай его целиком, затем доработай
> проект в этой папке так, чтобы он **полностью автономно** генерировал ежедневный
> подкаст про машины Octane Rent и был готов к публикации в YouTube Music по RSS.
> Начни с **тестового режима, который работает без единого платного ключа**.

---

## 1. Контекст и цель

Компания **Octane Rent** (`https://octane.rent`) — прокат люксовых авто (Дубай, Абу-Даби,
Шарджа, Майами). Нужен продукт: **1 машина = 1 подкаст-выпуск, раз в день, автоматически**.

Финальная схема (уже заложена в код):
1. Взять следующий **необработанный** URL авто из sitemap сайта.
2. Распарсить страницу (название, цена AED, характеристики, фото).
3. Сгенерировать **сценарий-диалог двух ведущих** (LLM).
4. **Озвучить** двумя голосами и склеить в один MP3.
5. Обновить **RSS-фид** (`feed.xml`).
6. Опубликовать на **GitHub Pages**; YouTube Music / Spotify / Apple тянут выпуски из RSS.

Формат — **аудио** (видео не нужно: YouTube Music принимает подкасты по RSS).

## 3. Что нужно сделать (задачи)

### 3.1. Тестовый режим без платных ключей — ГЛАВНОЕ
Добавь провайдер TTS `gtts` (библиотека `gTTS`, бесплатно, без ключа) в `src/synthesize.py`:
- При `TTS_PROVIDER=gtts` каждая реплика озвучивается через gTTS;
- «Два ведущих» имитируй сменой параметра `tld` (напр. `com` и `co.uk`) и/или лёгким
  сдвигом высоты/скорости, чтобы голоса отличались;
- Формат вывода — MP3, склейка через pydub (ffmpeg уже требуется).

Добавь **CLI-флаг/режим** `--test` (или `MODE=test`), который:
- ставит `SCRIPT_PROVIDER=none` (офлайн-шаблон) и `TTS_PROVIDER=gtts`;
- прогоняет **полный цикл на реальном sitemap octane.rent** (сеть тут открыта);
- кладёт реальный `episodes/*.mp3` и обновляет `feed.xml` и `state.json`;
- не требует ни AWS, ни Gemini, ни GitHub — только `pip install` и `ffmpeg`.

Результат теста: команда `python -m src.main --test` создаёт **настоящий MP3-выпуск и
валидный RSS локально**, за один запуск, без ручных действий.

### 3.2. Автономность и надёжность
- Скрипт должен отрабатывать полностью сам, без интерактивных вопросов.
- Обработай ошибки сети/парсинга: если одна машина не парсится — залогируй и возьми
  следующую (не падай целиком).
- Если новых машин нет — корректно завершайся (не дублируй выпуски).
- Идемпотентность: повторный запуск в тот же день не должен ломать state/feed.
- Все пути — относительно корня репозитория (уже так сделано в `config.py`).

### 3.3. Проверка парсинга на живом сайте
- Прогони `fetch_car.collect_car_urls()` и `parse_car()` на реальном octane.rent.
- Если селекторы цены/характеристик/фото не совпадают с реальной вёрсткой — **поправь
  их** в `fetch_car.py`, чтобы стабильно доставать: название, цену (AED),
  2–5 характеристик, главное фото. Убедись, что берётся именно **английская** версия
  страницы (без языковых префиксов `/ru/`, `/de/` и т.д.).

### 3.4. Качество аудио-выпуска
- Длительность выпуска ~1.5–3 минуты.
- Между репликами — короткие паузы (уже заложено).
- Опциональная заставка `assets/intro.mp3`, если файл есть.
- Тегируй MP3 (artist/album/title).

### 3.4a. Формат-шоу и уникальность (уже реализовано — сохранить)
- Формат «Octane Drive Stories»: ведущие + гость + эксперт Дарья + рубрика + розыгрыш.
  Всё в `src/angles.py` (`plan_episode`, `build_system_prompt`), описание — `PROMPTS.md`.
- `generate_script.generate(car, episode_index)` чередует гостя/историю/эксперта/рубрику и
  включает розыгрыш каждый 3-й выпуск. НЕ ломай ротацию.
- **Грундинг фактами:** `src/knowledge.py` тянет `octane.rent/policies.json` и `company.json`,
  кэширует в `knowledge.json`, и эксперт говорит ТОЛЬКО эти факты. В `--test` сеть открыта —
  проверь, что факты реально подтягиваются; если нет — работает `VERIFIED_FALLBACK`.
- **Реплики имеют 4 спикера** (A/B/G/E). Для gTTS в тестовом режиме сделай разные голоса на
  роли (например, меняй `tld`/скорость по спикеру), для Polly уже есть `POLLY_VOICE_A/B/G/E`.
- LLM-провайдер по умолчанию — **openrouter** (бесплатный, OpenAI-совместимый,
  модель `meta-llama/llama-3.3-70b-instruct:free`, ключ `OPENROUTER_API_KEY`). Groq — запасной.
  В `--test` LLM не нужен (шаблон уже даёт полноценный эпизод с гостем и экспертом).
- **Честность (не ослаблять):** гость — иллюстративный персонаж, не «проверенный отзыв»;
  эксперт не выдумывает правил; розыгрыш не называется «прямым эфиром».

### 3.4b. Видео + YouTube (уже реализовано — проверить и довести)
- `src/subtitles.py` делает SRT из таймингов сегментов (`synthesize` их возвращает).
- `src/build_video.py` (ffmpeg) собирает MP4: заставка (название авто + Octane) + фото
  машины на фоне + вшитые субтитры + плашка `octane.rent`. Требует ffmpeg и шрифт
  (Poppls/DejaVu). Проверено на синтетике; проверь на реальном фото и длинном аудио.
- `src/youtube_upload.py` грузит видео на канал через YouTube Data API (OAuth refresh-token),
  ставит title/description/tags/category и дорожку субтитров. `get_youtube_token.py` —
  разовое получение токена. Не коммить видео в репозиторий (оно идёт на YouTube).
- Тумблеры: `VIDEO_ENABLED`, `YOUTUBE_ENABLED`, `RSS_ENABLED`. В `--test` YouTube выключен.
- Для gTTS в `--test`: сделай разные голоса на роли A/B/G/E (напр. менять `tld`), чтобы
  ведущие/гость/эксперт звучали по-разному; субтитры и видео должны собираться и в тесте.

## 4. Критерии приёмки (Definition of Done)

Проект считается готовым, когда ВСЕ пункты выполнены и проверены:

1. `pip install -r requirements.txt` проходит без ошибок (плюс системный `ffmpeg`).
2. `python -m src.main --test` за один автономный запуск:
   - берёт реальную машину с octane.rent,
   - создаёт непустой `episodes/<дата>-<slug>.mp3` (проигрывается, длительность > 30 сек),
   - обновляет `feed.xml` — валидный RSS с `<enclosure ... type="audio/mpeg">`,
     iTunes-тегами и правильным `PUBLIC_BASE_URL`,
   - записывает URL в `state.json` (повторный запуск берёт следующую машину).
3. `feed.xml` проходит валидацию RSS (проверь любым валидатором/скриптом; enclosure,
   даты в RFC-2822, itunes:image, itunes:duration присутствуют).
4. Второй запуск `--test` создаёт **другой** выпуск (следующая машина), не дублирует.
5. Нет интерактивных запросов, нет падений на одной проблемной странице.
6. Продакшн-путь настроен: `daily.yml` валиден; переменные документированы в README.
7. Секреты/ключи нигде не захардкожены; `.env` в `.gitignore`.

## 5. Как проверять (обязательно прогнать)

```bash
python -m pip install -r requirements.txt
# (в CI/локально) sudo apt-get install -y ffmpeg   # или brew install ffmpeg

# Полный автономный тест-прогон:
python -m src.main --test

# Проверь, что появился MP3 и он не пустой:
ls -la episodes/
python - <<'PY'
from pydub import AudioSegment
import glob
f = sorted(glob.glob("episodes/*.mp3"))[-1]
a = AudioSegment.from_file(f)
print("episode:", f, "duration_sec:", len(a)//1000)
assert len(a) > 30_000, "выпуск слишком короткий"
print("OK audio")
PY

# Проверь валидность RSS:
python - <<'PY'
import xml.dom.minidom as m
x = open("feed.xml").read()
m.parseString(x)  # бросит исключение, если XML невалиден
for t in ["<enclosure", "audio/mpeg", "itunes:", "<pubDate"]:
    assert t in x, f"нет {t}"
print("OK feed")
PY

# Идемпотентность/следующая машина:
python -m src.main --test
git --no-pager diff --stat 2>/dev/null || true
```

Приложи в финале краткий отчёт: какие машины взял, длительность выпусков, что
правил в селекторах, что осталось на продакшн (какие ключи нужны от пользователя).

## 6. Ограничения и правила

- **Не меняй архитектуру** без причины: провайдеры TTS/LLM должны оставаться
  переключаемыми через `.env` (`TTS_PROVIDER`, `SCRIPT_PROVIDER`).
- Язык подкаста — **английский** (голоса и промпт под EN).
- Не коммить секреты. Не удаляй `.gitignore`, `.nojekyll`.
- Держи всё в этой папке; не плоди лишних top-level файлов сверх нужного.
- Пиши код чисто и с обработкой ошибок; логируй шаги в stdout.
